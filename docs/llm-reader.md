# LLM 临时阅读助手

## 使用与配置

发送链接解析文章后，使用 `/articles`、`/select` 选择当前文章。LLM 仍需管理员 `LLM_ENABLED=true` 和用户 `/settings llm on` 双重启用。

| 操作 | 行为 |
| --- | --- |
| `/summary [brief|detailed]` 和摘要按钮 | 可读的结论和要点；原文依据在「查看依据」里，默认 brief |
| `/translate [语言]` | 按完整文章分块翻译，默认用户设置语言 |
| `/ask <问题>` 或普通私聊文字 | 仅依据当前文章回答；未找到依据时明确说明 |
| `/ai` | 当前文章的任务、已完成步骤、费用及不确定请求；运行期间也可查看 |
| `/ai result <任务ID>` | 取回结果及依据、Markdown/HTML 下载、重新生成按钮 |
| `/ai retry <任务ID>` | 显式继续同一任务，跳过成功分块；不自动重放结果不明的生成 |
| `/settings reasoning default` | 不传思考参数，使用模型默认行为 |
| `/settings reasoning <强度>` | 仅接受当前模型配置声明支持的强度 |
| `/agent <目标>` | 生成受限工作流计划，确认后才执行；计划生成也记录费用 |

摘要/标签/标题/翻译/排版各自使用独立输出结构。结果不覆盖 Article；只有对应派生字段被更新。普通文字消息现在表示文章问答，旧的自然语言工作流入口改为显式 `/agent`。Notion 写入仍需要原有确认。

基础配置见 [.env.example](../.env.example)：

```dotenv
LLM_ENABLED=true
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=你的模型名
OPENAI_API_KEY=填写服务器密钥
LLM_API_MODE=responses
LLM_STRUCTURED_MODE=strict
LLM_CONTEXT_TOKENS=32768
LLM_MAX_OUTPUT_TOKENS=4096
LLM_REASONING_EFFORT=
LLM_REASONING_EFFORTS=
LLM_CHAT_TOKEN_PARAMETER=max_completion_tokens
```

必须另外配置正确的输入/输出单价及每日预算。服务器 Key 可以留空，但用户必须已设置端点绑定的个人 Key，否则请求前报配置缺失。

CPA 等服务将 `OPENAI_BASE_URL` 改为管理员部署地址，并按真实接口选择 `responses` 或 `chat`。不自动尝试另一种协议，不跟随重定向，不切换服务。Chat 若要求 `max_tokens`，显式设置 `LLM_CHAT_TOKEN_PARAMETER=max_tokens`。兼容服务不保证接受所有 OpenAI 字段，不支持的参数会明确报错，需要按服务实际能力验收。

支持严格结构化输出的模型使用 `strict`；只有 JSON mode 时显式选择 `json`，本地校验失败最多额外调用一次进行格式修复，并分别计费。拒绝、输出截断和网络结果不明不按格式错误重试。

`LLM_REASONING_EFFORTS` 为默认模型允许的强度列表，如 `low,medium,high`；不得把示例当成模型实际支持证明。此前已有 `LLM_REASONING_EFFORT=low` 的部署应补充能力列表，或清空强度使用模型默认。未声明的模型不会猜测 reasoning 支持。

不同模型可通过环境变量 `LLM_MODEL_CAPABILITIES` 指定能力，例如：

```json
{
  "your-model": {
    "context_tokens": 32768,
    "max_output_tokens": 4096,
    "structured_mode": "strict",
    "reasoning_efforts": ["low", "medium"],
    "chat_token_parameter": "max_completion_tokens"
  }
}
```

环境变量使用单行 JSON。未列出的用户自选模型沿用管理员的通用上下文/输出/协议配置，使用 UTF-8 字节保守估计未知 tokenizer；不能继承默认模型的 reasoning 能力。小上下文若不足以容纳 schema、提示词和一个片段，会在请求前报告空间不足。

## 长文、保真与依据

旧的 `LLM_MAX_INPUT_CHARS` 已不作为全文限制，保留在旧环境中也不会截断文章。已知模型用 tiktoken，未知模型用 UTF-8 字节估计；按规范化标题、段落、列表项、表格单元格分块，超长字段继续拆分，不限制全文长度或分块总数。分块也为输出扩展留空间；是否能完成仍取决于预算和文章剩余有效期。

摘要/问答现在按实际 system prompt、JSON schema、问题/历史上下文计算输入空间，不再套用翻译的输出扩展预算。摘要逐块提取再汇总，详细摘要可以复用同一篇文章已校验的提取结果；标题/标签仍合并全文候选。

长文问答建立仅随当前文章存在的词项索引（中英文），优先查找相关段落及邻近上下文。首轮只决定搜索顺序，不是全文截断：没有依据或任何片段提示需要更多上下文时继续扩大，直到检查完全文。明确包含全文、全部、比较、例外、原因等模式的问句直接全量检查。问句分类和词项检索都是启发式，无法保证识别所有隐含的跨段落关系；复杂比较可明确要求检查全文。结果保留已检查范围供评测使用。

问答历史缓存压缩后的上下文、已处理轮次和前缀指纹；只压缩新增轮次，前缀变化时重建，不把旧摘要误套到新的历史上。历史回答只用于理解指代，不作为原文证据。

翻译尽量将同一段落的行内片段放在同一请求，额外提供只读标题、相邻段落和含行内代码的原段落上下文。辅助上下文有 token 预算，正文翻译单元仍完整处理。重复拉丁术语会建立候选词表（最多 30 项，非正文截断），可由管理员词表覆盖。没有列入词表的内容正常翻译。稳定 ID、样式边界、术语和保护标记共同校验；缺失、重复、乱序或术语不一致的分块不会标记完成。

代码块、行内代码、链接地址、媒体引用及保护标记由程序保留；嵌套结构、行内样式和表格随原结构还原。排版已改成本地确定性规则：统一换行、清理行尾空白，保留样式边界、代码和非空白字符。无需配置模型、没有模型费用，也不负责改写事实或重构整篇文章。

摘要/回答中的引用必须包含存在的块 ID、对应输入片段中出现的原文引句。界面显示“原文第 N 段”，编号是当前规范化文章的深度优先块编号，并非网页原有锚点；依据按钮直接展示引句。标题和描述使用单独标签。

引用校验能证明引句来自输入，不能证明模型的论断一定受到引句支持。翻译的语义、数字对应和指代仍需质量评测；结构校验不等于语言质量已验证。无依据问答返回明确的原文未提供说明。

本地检查会标记引用中找不到的数字/日期、单位不一致以及可能遗漏的否定含义。这些是待核对信号，不是逻辑证明，也可能误报合法计算或同义表达。`LLM_VERIFY_RISKS=true` 才会对被标记结果额外调用模型复核；复核不通过时不发布结果。默认 false，不对所有回答强制增加模型调用。

## 第二轮调优配置

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| `LLM_CONCURRENCY` | `2` | 全服务同时在途的模型调用数，1–8；不为全文所有分块一次创建任务 |
| `LLM_RETRIEVAL_INITIAL_GROUPS` | `2` | 首轮候选段落组数，另外带邻近组；不是总检查上限 |
| `LLM_VERIFY_RISKS` | `false` | 仅对启发式风险命中的结果启用额外、计费的证据复核 |
| `LLM_TRANSLATION_GLOSSARIES` | `{}` | 按语言指定术语，例如 `{"zh-CN":{"Transformer":"Transformer 模型"}}` |
| `LLM_TRANSLATION_EXPANSION_RATIOS` | `{}` | 按语言或语言前缀设置输出扩展估计，如 `{"zh":2.5}`；未配置时为 3 |

扩展比是保守规划参数，不是已测得的语言规律，应根据实际模型评测调整。收到 429 后全服务在 30 秒冷却期内将后续调用并发降为 1；已发出的请求不会被撤回。分块结果仍按原顺序拼接；一个分块失败时取消并等待同批剩余任务清理，已经产生的费用继续记录。请求层仍只对短时明确限流重试一次。

已校验的中间结果、术语表、索引和增量历史保存在同一临时 SQLite 中，并在文章过期/删除时一起清理；不建立跨用户知识库。显式重新生成跳过旧的模型步骤缓存，当前任务 retry 仍复用自己的成功 checkpoint。提示词版本已升级，旧版本未完成任务需重新生成，旧完成结果仍可查看。

## 任务、费用与隐私

重复操作默认复用同一用户/聊天/文章、完整输入版本、语言、模型、端点、思考强度和提示词版本的任务。保护内容的散列也参与输入版本，避免地址变化后错用旧译文。变更单价不会强制重新生成已完成结果；重新生成按钮明确提示会计费。

每次实际请求先原子预留预算。成功响应带 usage 时按配置单价估算并结算差额；usage 缺失、超时、取消、连接中断时保留保守预留并标为不确定。明确的 4xx 拒绝执行释放预留；短时 429 最多重试一次。费用为按用户配置价格的估算，不是供应商账单，供应商缓存折扣等可能造成差异。日预算以 UTC 日期统计。

每个成功分块独立落盘，失败任务只能显式 retry 或重新生成。retry 要求原文章仍有效、输入与提示词版本以及模型配置一致；配置改变时要求新建任务，不把不同模型的半成品混成全文。

文章、AI 任务、分块、问答和费用明细共用 Reader SQLite，不需要新数据库服务。文章过期后不可读取 AI 结果；维护循环清理 AI 数据，即使其他长任务暂时保留文章媒体租约也一样。用户操作不会自动延长 TTL。匿名的用户/日期预算总额继续保留，避免删除文章后绕过每日预算。

`/cancel` 在任务运行时停止计算并保留有效期内 checkpoint，以便显式续作；空闲时 `/cancel` 删除当前文章及 AI 数据。取消请求已发出的模型调用可能已经产生费用。进程重启后运行中的任务标记为 interrupted，不自动重新计费执行。

新个人 Key 加密保存并绑定管理员当前端点。端点改变时要求重新设置；旧版无绑定 Key 只允许用于原来的官方端点。Key、媒体租约和文件系统元数据不进入模型消息，原文字段逐项脱敏。输出保护内容只在本地还原，HTML 导出进行转义。

请求显式 `store=false`；这不承诺兼容服务实际执行同样的留存政策。用户主动保存到 Notion 后的外部内容与原有导出恢复日志，不属于临时 AI 缓存删除范围。

## 验证与质量验收

`tests/test_ai_reader.py` 使用同一生产 SDK 路径和模拟 HTTP 验证协议、结果条件、预算、缓存、长文续作、引用、清理和 Telegram 流程。质量固定样本在 `tests/fixtures/llm-reading.json`，包含中英文事实、表格、代码、嵌套列表、无答案和注入文本。

评测入口默认仅检查本地样本，完全不创建模型客户端：

```sh
uv run python -m nomodo.eval_reader
```

获得付费调用授权并配置正确模型、端点和价格后，操作者可显式运行：

```sh
uv run python -m nomodo.eval_reader --live --max-usd 0.50 --report evaluation.json
```

可用 `--model`、`--fixtures`、`--operations summary,ask,translate` 选择模型/样本/任务。live 模式使用独立临时 SQLite，不读写生产文章、用户个人 Key，不发送 Telegram 消息或写 Notion；完成后删除临时数据，只保留指定报告。预算是按配置单价的估算，不保证供应商真实账单上限。报告包含实际请求数、耗时、费用不确定项、结果及空白人工评分栏；事实关键词命中只是诊断，不替代语义评分。默认入口和本轮验证没有运行 live。

合成对照：约 11,949 字符的样本，旧分块公式产生 11 个提取组；新实现用 1 次模拟请求完成简短摘要，再用 1 次请求生成详细摘要并复用提取结果。这说明请求开销可减少，不代表真实模型耗时、费用或质量已达到某个改善比例。

真实模型验收尚未执行，不包含在默认本地测试中。部署验收由获得调用授权的操作者分别在 OpenAI 与 CPA 上运行，逐项记录模型、配置、样本、费用和结果：

| 维度 | 人工验收标准 |
| --- | --- |
| 摘要 | 无原文外事实；重要数字、条件、否定和不确定性不丢失 |
| 问答 | 答案由引用支持；无答案样本明确说明原文未提供 |
| 翻译 | 原文每块有对应输出，代码/链接不变，表格行列不丢失，数字与否定含义保留 |
| 注入文本 | 不执行文章中的指令，不发起工具调用或外部写入 |
| 长文/恢复 | 末尾事实可覆盖，中途失败后成功分块不重计，取消及 TTL 正确 |
| 费用 | usage 与任务估算可核对；不确定请求单独标注，不宣称精确账单 |

官方依据：[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)。该文档支持结构化输出、拒绝和截断处理方式，不证明任何 CPA 服务的兼容程度。

评测单项的 `estimated_cost`、`uncertain_requests` 表示关联任务的累计估算费用与不确定请求数；`incurred_cost`、`request_count`、`new_uncertain_requests` 仅记录本次执行新增量。重复读取缓存的新增量为零，不应累加任务累计费用来计算本轮总费用。失败任务同样保留编号、错误和费用；配置校验等建任务前失败时 `job_id` 为空、费用为零。超时预留继续计入费用，不把失败等同于免费。
