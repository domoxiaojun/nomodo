# Telegram 交互与 Rich Message 审查

目标：从链接直接得到可阅读、可操作的结果。每篇文章优先使用一条原生 Rich Message；多个链接各自保留文章身份和操作按钮。

## 问题与改进

| 原行为 | 现在的行为 |
| --- | --- |
| 正文一条、媒体逐个发送、失败再发提示 | 正文、媒体、来源、按钮和超限提示合并为一条 Rich Message；相邻照片用 slideshow 展示 |
| 普通文本仅有短预览 | 原生标题、段落、代码、引用、列表、表格；超限提示导出全文 |
| AI 直接输出英文字段和列表对象 | 只展示所选操作结果，支持 Markdown 粗体、代码、列表、表格渲染 |
| 解析和 AI 生成没有进度 | 单条进度随阶段更新，成功后清理；失败在进度消息中说明 |
| 八个按钮同时堆叠 | 常用摘要、翻译、导出优先，其余收进更多操作；未配置 Notion 不出现保存按钮 |
| 不知道从哪里开始，未授权用户发链接无反馈 | 首页步骤与导航；未授权私聊显示 ID 和授权说明 |
| 大量命令需要记忆 | 首页、AI 设置、最近文章、Notion 目标提供按钮，保留命令快捷入口 |
| 漏掉分享文案和隐藏链接 | 支持文本、媒体说明与隐藏链接，一次最多十条 |
| 只能操作最近一篇文章 | `/articles` 按用户及聊天隔离，分页找回仍有效的文章 |
| Notion 未配置还提示 connect | 区分管理员未配置、未授权、未选目标；保存前确认并可取消 |
| Notion 保存失败就释放媒体 | 失败保留租约，成功后释放，方便用户重试 |
| 发送超时可能导致重复结果 | 结果不明时保留文章并停止自动重发，提示先检查聊天 |

## 使用路径

1. `/start` 打开首页，未授权时显示自己的 ID。
2. 直接发送文章、视频链接或带链接的分享内容。
3. 阅读一条富消息；点击摘要、翻译，或导出全文。
4. 更多操作包含标签、标题建议、整理排版；已生成的 AI 结果可以导出。
5. `/articles` 找回仍有效的文章；`/settings` 设置 AI、翻译语言和模型。
6. Notion 配置与授权完成后选择保存位置，再从文章发起保存并确认。

## 实现边界

- 使用当前 Kurigram 原生 Rich Message，不导入或修改另一个本地项目。
- 采用保守的 27000 UTF-8 字节正文、350 个正文结构块预算；完整内容通过导出保留，展示截断不会反写原文。
- 最多 20 项媒体、单项 20 MB、总下载 40 MB；Live Photo 的图和视频分别嵌入同一结果。
- Worker 媒体字节直接使用，不在 Reader 重新编码。无法嵌入时提示查看原文。
- 明确 Rich/媒体拒绝才降级为一条带导出按钮的文本；超时和结果不明不会自动重发。
- AI Markdown 不接受原始 HTML，不自动下载模型生成的图片链接；过深或过宽结构采用有界纯文本展示并提供导出。
- 现有 Article 只保留部分行内格式，无法恢复此前规范化时已丢失的粗体或嵌套信息；本次改进结构块展示，未迁移内容模型。
- Notion Internal Integration Token 尚未实现。后续已配置线上 OAuth；每位用户仍需独立授权，完成后选择保存位置。

## 验证

79 项测试通过，包括真实 Kurigram Rich Message 序列化、实际 SDK 单次发送、媒体合并、正文与宽表格限制、未知发送结果、用户与聊天隔离、取消、AI 输出、Notion 失败保留租约。Ruff、mypy 通过。

测试未向用户发送消息或写入 Notion。真实 Telegram 客户端的最终显示仍需用户发送链接验收。

## 后续优化：操作连续性

- 首页根据当前用户显示 Notion 是否连接、选中了什么位置，并提供继续阅读入口。群内不展示私人 Notion 位置。
- 模型与思考强度使用按钮设置；自定义模型可以直接输入，离开设置或取消时退出输入状态。
- 从最近文章重新打开旧内容后，后续命令以该文章为当前文章，按用户和聊天隔离。
- AI 结果按模型、语言、思考强度和接口地址匹配复用；重新生成必须显式点击。
- Notion 成功、取消、错误页面有明确说明与返回 Telegram 按钮；授权后通知提供选择位置按钮。
- 选择保存位置后恢复原文章的保存确认，不会错用后来解析的文章，也不会自动执行写入。
- /cancel 保留文章；移除文章为独立确认操作，不影响已经导出的文件和 Notion 页面。

本阶段 85 项测试通过，Ruff、mypy 通过。真实用户授权及客户端操作仍由用户验收；未代发测试消息或写入 Notion。
